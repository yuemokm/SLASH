# 预约管理简短 PRD

> 来源：`资源/预约需求.md`（仅依据本次合成需求整理）。未明确事实均标记为待确认。

## 1. 目标
面向小型活动运营人员，提供客户预约登记与预约列表查看能力。系统应在提交时校验关键字段和重复预约，成功后给出确认并进入列表；管理员可取消尚未开始的预约。当前范围不包含短信、支付和用户登录。

## 2. 字段与规则
- **客户姓名**：必填；长度、特殊字符及前后空格处理待确认。
- **手机号**：必填，且必须为11位数字；是否限定号段、是否脱敏展示待确认。
- **预约日期**：必填，不得早于今天；“今天”依据的时区、日期格式及是否允许当天预约待确认。
- **预约状态/操作信息**：需求明确管理员可取消尚未开始的预约；状态枚举、取消后是否保留记录、取消原因及操作权限细则待确认。
- **唯一性**：同一手机号在同一天不能重复预约；需在提交时拦截，并向用户说明失败原因。是否区分已取消记录、是否允许取消后重新预约待确认。

## 3. 主流程
1. 运营人员打开预约登记页，填写客户姓名、手机号和预约日期。
2. 点击提交，系统校验必填项、手机号格式、预约日期及“手机号+日期”重复性。
3. 校验失败：显示对应错误信息，保留已填写内容，允许修改后再次提交。
4. 校验通过：创建预约，显示提交成功确认，并进入预约列表。
5. 在列表中查看预约记录；管理员对尚未开始的预约执行取消。取消后的展示、撤销能力及异常反馈待确认。

## 4. 验收清单
- [ ] 登记页包含客户姓名、手机号、预约日期三个必填字段。
- [ ] 姓名、手机号或日期为空时不能提交，并保留输入。
- [ ] 非11位数字手机号不能提交，并显示明确错误。
- [ ] 早于今天的预约日期不能提交；“今天”的判定规则待确认后验收。
- [ ] 同一手机号同一天重复预约被拦截，并保留输入。
- [ ] 合法提交显示成功确认，并进入预约列表。
- [ ] 管理员可取消尚未开始的预约；其他状态处理待确认。
- [ ] 不引入短信、支付或用户登录功能。
- [ ] 对状态、时区、日期格式、取消记录及权限等待确认项补充规则后再做最终验收。
