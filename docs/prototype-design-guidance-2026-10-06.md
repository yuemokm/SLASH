# 原型设计建议与分段制作

需求：F10 / PF08。用户反馈旧生成原型“非常丑不可用”，因此验收必须同时看实际任务能否完成和渲染结果能否用于工作，不能只检查 HTML 存在或按钮可点击。

`main/prototype-guidance.ts` 统一维护简短业务建议，由可编辑的默认协作提示和 `prototype` 工作流引用，不放入不可修改的宿主安全边界。用户明确的范围、视觉方向、现有界面和实际读取的规范优先；企业工作台的信息密度和操作效率是适用默认，不能强制普通页面、消费产品或用户指定风格照搬。已有用户自定义系统提示词不迁移、不覆盖；采用原型工作流时仍会收到可由用户本次输入覆盖的建议。普通会话使用自定义提示词时，由用户自己的提示与资料决定设计。

旧默认兼容：`systemPromptView` 只识别本次增加建议前的一个已知默认原文，比较保存的原字符串，不去空格、不统一换行、不猜测相似文本。精确匹配时在读取结果中返回当前默认并标记 `isDefault=true`，不写回 `system-prompt:v1`，原保存时间保持。其他合法已保存内容按原字符串返回。这样旧默认配置的普通原型聊天也能使用本次建议，自定义提示仍由用户控制。之前已接受任务的 `system-prompt:run:<id>` 快照不经此兼容解析，执行继续读取固定快照；新任务才读取当前有效默认。保存接口既有的输入校验与 trim 行为未改，兼容识别不使用校验后的 trim 值。

建议要求先明确任务、区域、关键数据和状态，按需读取授权参考和 skill，统一颜色/字体/间距/控件与状态。关联列表、详情等工作面共享状态；按钮要完成业务动作，反馈、取消及适用边界状态保持连贯。没有实际读取某个规范不能声称使用它。

制作延续现有 Pi 和草稿工具：按复杂度先保存紧凑、布局完整且可运行的首稿，接着按区域读取同一待应用草稿并增量补齐，每段保持文件可运行。单 HTML 同样可以分段制作，用户要求单文件不会变成强制拆分项目。每次 `write_draft` 仍需提供该次完整文件；后续通过 `read_draft` 获得 `changeId` / 最新哈希并用 `edit_draft` 修订，沿用版本检查与待应用卡。不添加字符数硬上限或自动改写产物；分段生成属于制作建议。首稿、占位或缺失功能必须保持未完成表述。

交付前分别检查布局和操作。有工具时查看真实渲染截图，执行主要任务和必要边界状态，发现问题先修复；正式原型验收读取已应用成果，因此待应用稿尚不能宣称已有正式验收证据。无法截图或执行时明确未验证范围。静态通过、有限 DOM 断言、视觉判断和业务完整性是不同证据。

## 实际原型评审标准

每项记录“缺失/不可用、部分可用、清楚可用”和对应截图或操作证据，不用一个总分掩盖核心失败。

| 项 | 判断依据 |
| --- | --- |
| 范围与主任务 | 用户指定区域真实存在；工作面承载任务，主操作清晰可找到 |
| 层级与密度 | 标题、筛选、摘要、数据、详情有层级；文字易读、对齐，首屏有有效业务内容 |
| 视觉一致性 | 颜色、字号、间距、控件尺寸与状态一致；主次操作、选中与风险强调有意义 |
| 工作面协调 | 筛选、选中、列表、详情使用同一数据状态；无重叠、遮挡、截断关键动作 |
| 任务闭环 | 核心动作产生实际变化；保存反馈、取消行为一致，无无效按钮或虚假成功 |
| 边界处理 | 任务适用的空结果、未选中、输入失败及异常给出可理解的下一步 |
| 真实证据 | 审阅完整视口和操作后状态截图；操作断言与加载错误按实际结果记录 |

强制区域缺失、核心操作失效、内容/动作被遮挡或虚假成功均直接判失败。截图评审需要人工或具备视觉能力的 Agent；提示词回归不能证明真实模型已生成可用页面。特定测试的领域、布局和色彩来自该次用户 brief，不写入通用建议。

本轮真实测试 brief 指定移动 SFA“上地图、下工作台”。必须审阅 390×844 的移动视口及关键操作后截图，检查触控、垂直滚动、详情与表单遮挡，桌面视口不能替代该验收。地图/列表选择联动、筛选、任务详情及指派操作是此场景的业务检查，来自 brief，未固化进通用生成建议。

流程见 [Mermaid 源文件](diagrams/prototype-design-guidance.mmd)。
