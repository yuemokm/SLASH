# 真实任务测试与修复记录

用户目标：复现任务执行失败，用真实模型检查实际业务任务，并判断原型是否可用。测试在独立 Electron、独立数据目录和合成业务资料中进行；不是在用户业务项目中重放操作。原型代码由 Slash 的模型和工具生成，没有手工改写 HTML 代替应用产出。

## 场景与判定

门店作战中心：六个门店、三位外勤、三项任务，上方离线示意地图、下方工作台；检查筛选、搜索、地图/列表联动、任务详情与改派。手机 390×844，桌面 1440×900、1280×800。生成成功、保存版本、浏览器行为、视觉可用性分别判断，不能互相替代。

## 已证实并修复的软件问题

- 失败任务的明确恢复可以承接原任务尚未应用的普通草稿，沿用同一卡和真实恢复关系；会话精确输入“继续”可进入官方恢复。普通新任务不接管其他任务草稿。
- pending 编辑缺失 ID 不再笼统报版本变化；读取正式文件时明确其已保存状态，不再误称“草稿尚未应用”。旧 ID 会被明确拒绝，重新读取后可按当前哈希创建新草稿。
- 应用操作加入已有操作记录，区分 UI、IPC 与宿主入口。保留运行中应用能力以及版本和资源锁检查。
- 原十分钟/四十次工具预算会截断仍在推进的复杂任务。统一改为每次尝试三十分钟、一百二十次工具的有限预算；取消、外部结果未知、Pi 原生重试与压缩规则不变。
- 输出上限中断的恢复明确要求先提交小而完整的工具调用，再逐块推进。错误显示未验证兼容限额的实际数值和核对入口，不把兼容值当成供应商能力。
- 原型默认协作建议补充工作面层级、中文字体、移动布局、共享业务状态、分段编辑与实际视觉/交互验收。精确旧默认可以读时采用新建议，用户自定义提示不被覆盖。建议生效不等于生成质量通过。

## 真实测试暴露的限制

1. Responses 实际发生缺少终态事件；Completions 也实际发生连接错误和一次可恢复的 429。单次连接健康测试成功不能证明业务任务稳定。
2. 第一次正式续作在实际十分钟边界失败，保留约 29 KB 草稿。调整预算后第二次续作完成，但期间草稿提前被应用，旧读取提示导致模型三次使用过期 ID。旧记录不能确定应用调用者，不能归因于权限模式自动应用。
3. 旧应用文件的浏览器诊断发现手机筛选控件越界、地图标记触控尺寸不足、标签拥挤和桌面密度差、外勤状态筛选无效。行为测试中已有部分功能正常，不构成可交付结论。
4. 首次定向视觉反馈读完资料后达到输出上限：实际 output=12000，只有思考块，没有正文或工具调用，没有修改文件。12000 来自宿主未知能力兼容值，并非用户填写或上游正式声明。离线真实 Pi 请求构造确认关闭思考字段已经透传，但该端点实际控制效果尚未证实。

最后一次官方恢复的终态见文末。复杂任务与原型质量未全部通过，未对旧稿补造正式浏览器通过结果。
