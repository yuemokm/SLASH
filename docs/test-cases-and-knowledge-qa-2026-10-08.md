## 测试用例创建

单一 `.testcases.json` 是可版本化的规范成果；界面负责可读呈现，Markdown/XLSX由同一内容确定性导出，避免维护两份互相漂移的可编辑原稿。

每个用例包含编号、模块、标题、优先级、类型、前置条件、测试数据、逐步操作与预期、需求/规则关联、来源及待确认问题。类型覆盖正常、异常、边界、权限、状态/数据，按真实任务选择；无证据的后台逻辑或性能阈值只能标为候选/待确认。

模型提出用例内容和已读来源引用，宿主从本 Run 的来源回执补齐文件/版本/哈希/位置。仅目录和文件信息不计为已读正文；不存在的需求 ID、来源或模型自称的“已通过”不能形成正式验证事实。结构校验无法证明业务预期正确，预期与来源是否相符需要内容核对和真实案例评测。

执行状态固定为“未执行”，和生成验收分开。现有原型浏览器用例仍是具有选择器与可执行断言的另一种规格；首版不自动将手工步骤转换成浏览器测试，不把用例数量当覆盖率或通过率。

复用 Pi、工作流、ChangeSet、授权及版本校验。Plan 只分析；Build 生成待应用成果。普通增量编辑、保存与导出均重新校验规范，导出复核授权和目标版本。Excel 正文作为字符串写入，业务资料不成为公式。

## 知识库与问答架构

采用 Supabase PostgreSQL + pgvector 存储内容块及语义向量，并与关键词检索融合；Vercel 运行独立网页及受限服务端问答 API。Pi 继续作为 Slash 的 Agent 底座；问答只接收检索证据，不加载桌面工具，不引入第二套通用 Agent harness。

官方 [Supabase 混合检索](https://supabase.com/docs/guides/ai/hybrid-search)支持将关键词排名和语义排名融合。中文需预分词，不能直接把英文全文检索示例当成中文效果验收。

### 构建与更新

1. 用户选择知识库名称及明确资料清单，复用目录授权、Office 登记副本和现有文本解析。
2. 显示成功/部分/失败的解析覆盖；扫描 PDF、缺失图片或超限正文不能显示完整索引。
3. 按标题、段落、表格行分块。每块保留资料身份、原件/提取版本、定位、正文哈希和解析器版本；表格不得将不同业务对象的列值混接。
4. 通过专门配置的 embedding 服务生成真实向量。聊天模型不自动视为支持 embedding；索引与查询必须使用同一模型指纹和维度。
5. 只上传用户本次选择的资料集合，构建新索引版本；阶段状态、失败原因与已完成块可恢复。未完成版本不参与线上问答。
6. 构建完成后切换已发布版本；未改变的正文块复用，模型/维度变化则重建。停止分享、删除与访问撤销先禁止检索，再异步清理。

发布版本与本地资料状态分开。网页使用已发布快照，本地文件改变后显示“有更新待发布”；只有远端确认更新/撤销成功才显示同步完成。桌面离线时不承诺立即同步本地变化，收到的历史答案也不能从同事设备中远程抹除。

### 每次问答

访问检查 → 问题向量 → 在当前可访问知识库版本中进行向量/关键词检索 → 融合、去重及上下文限额 → 无桌面工具的模型回答 → 引用身份复核 → 答案与来源。

默认需授权访问，发布时可明确选择开放范围。Supabase Auth 与知识库成员关系隔离不同知识库；RLS按实际知识库授权过滤，不能仅检查“已登录”。用户问题不能指定任意 SQL、项目路径、模型端点或管理工具。公开分享若后续启用，须单独选择允许公开的资料。

资料不足时明确“当前资料没有依据”，存在冲突时并列来源，不把推断写成已确认事实。引用由宿主绑定此次检索命中和版本；真实引用存在不等于模型的解释正确，需要独立问答评测。

## MCP：管理与问答分开

官方入口为 [Vercel MCP](https://vercel.com/docs/agent-resources/vercel-mcp) 的 `https://mcp.vercel.com` 和 [Supabase MCP](https://supabase.com/docs/guides/ai-tools/mcp) 的 `https://mcp.supabase.com/mcp`。两者属于 Slash 创建、配置和发布应用时使用的管理连接；同事问答的运行 API 不调用这些管理 MCP。

现有远程连接只传地址，没有 OAuth，因此需要复用已安装 MCP SDK补齐授权提供者、浏览器登录回调、加密凭据与刷新。普通连接测试不会自动弹登录浏览器；令牌不进入 UI State、模型上下文或操作日志。连接地址/项目范围变更后重新核对授权。

Vercel 官方文档明确要求客户端审核；Pi 在支持列表中，不代表自定义 Slash Client自动被批准。实现预设与授权流程后，仍须真实登录/客户端兼容验证；不冒用其他客户端身份。必要时官方 CLI 可作为单独明确配置的发布路径，不能伪称 MCP 已连通。

Supabase支持项目范围、只读和功能组。官方成本、SQL及密钥等交互可能要求 MCP elicitation；保留真实用户交互，不默认使用 skip_elicitations，也不将“完全访问”冒充费用或网页登录确认。密钥通过专用界面/官方 Dashboard 输入，不写在聊天里。

统一工具目录分页并记录完整/部分覆盖，不把整个大型工具目录固定塞入模型上下文；取消/失效/未登录与网络失败分别呈现。已发出的外部操作超时继续标结果未知，不在重新授权后自动重发。

## 云端边界与当前待验证项

- Vercel服务端保存回答/embedding凭据；浏览器不得获得模型密钥、Supabase secret/service-role或MCP管理令牌。
- Supabase暴露表必须明确授权与RLS；新项目创建表不保证自动可由Data API访问。迁移后查询实际pgvector版本并执行访问隔离验证。
- 本轮不自动创建收费资源、改变现有云项目或发布真实资料。开发代码/模板先在本地验证；实际部署前需要可用账号授权、目标项目和实际资料集合。
- 回答模型、embedding模型与访问方式会作为独立配置，不在模型能力未知时静默猜测或降为关键词却显示“向量索引成功”。
