# 比赛 PPT 与实际产品演示提纲

2026-10-05，文本提纲。PPT 建议 9 页，演示约 3 分钟。用户确认的比赛关注点只有**落地价值**和**与成熟 Agent 的区别**；下述内容用于说明这两点，不新增评分标准。

主线：**让 PM 从真实资料形成 PRD 和可交互原型，再用可复查的依据、版本和实际运行结果完成修订。** 演示使用隔离项目与合成门店数据。真实来源只展示最小必要的字段片段，原件只读，不展示客户、人员、电话、完整地址、密钥或敏感全文。

## 9 页 PPT

| 页 | 标题与核心表达 | 画面/证据 | 讲述要点 |

| 1 | slash：面向 PM 的资料到交付工作台 | 实际会话与成果预览同屏 | 对象是要根据已有业务材料写需求、做原型并持续修改的 PM。今天展示一个真实小任务，不宣称覆盖所有产品工作。 |

| 4 | PM 专用约束：同一个字段有四种问题 | “03 机会门店主数据”列头与编码/名称两行必要片段；规则候选与引用位置 | A=仅正式落库、H=必填、O=新增展示、P=后续前端发起变更，各自独立。编码可展示且自动计算，P2=否；名称新建录入与后续改名不同。含义及阶段未明确的项保留待确认，不能靠模型补一个是/否。 |
| 5 | 同一规则落实到 PRD 和原型 | PRD 字段说明、原型只读编码/两种地址、约束落实位置 | 规则绑定具体成果位置与版本，便于追溯。真实基线中 HTML 两种地址权限正确，PRD 却混写；这说明需要跨成果人工核对，不能只看页面漂亮或摘录匹配。 |
| 6 | 真实运行：把失败变成可定位的问题 | 最终原型真实服务失败画面、保留的输入与重试 | 真实基线缺少服务失败入口。经过三次局部修订，实际选择模拟失败、合法输入提交、保留输入、切回成功重试均已复验。使用演示数据，仍是本地模拟而非真实服务联通。 |
| 7 | 三轮 HTML 修订，具体交互已复验 | 同一隔离项目的实际草稿差异、新的运行报告与截图 | HTML 独立 13 项交互全部通过；宿主另有 8 个场景通过，覆盖分别说明，不合并成业务总分。PRD/对照结论待各自新稿人工审核，正式落库阶段、导入范围、编码时机与接口继续保留待确认。 |
| 8 | 改了版本，旧的通过不能继续当交付依据 | JS/CSS 变化后旧报告过期；用户确认必检范围；真实导出提示 | HTML 不变，依赖变化也要重新核对。必检范围由用户确认，Agent 不能删掉失败用例后直接绕过。必检 ZIP 是核对过的网页快照，明确不包含同目录 PRD 等非网页附件。 |
| 9 | 区别落在 PM 的工作闭环 | 一条“来源→候选规则→成果位置→运行证据→修订/版本”的实际截图路径 | 成熟 Agent 提供推理、工具、编辑和上下文能力，slash 复用 Pi，不声称这些底层能力独有。产品区别是将资料对象、字段维度、来源版本、PRD/原型落实、运行证据和交付要求收进 PM 的日常流程，减少手工串联证据的步骤。价值由这次任务的可用成果和修订结果说明，不编节省百分比。 |

## 约 3 分钟实际产品演示分镜

| 时间 | 实际操作与镜头 | 旁白重点 | 录制验收/边界 |
| --- | --- | --- | --- |
| 0:00–0:20 | 打开隔离项目，展示会话与“机会门店新建”三份成果，镜头停在简短任务说明 | “用三份已有材料形成需求和原型，重点看规则如何落实和修订。” | 文件来自真实模型任务；门店名称、电话、定位等交互输入用合成示例。 |
| 0:20–0:45 | 打开来源引用，只展示工作表名、四个列头、编码/名称必要单元格；短暂展示副本处理回执 | “新增展示、必填、正式落库和后续变更是不同问题；资料版本也要能追溯。” | 原件不可编辑；不展示整张表、客户名单或制度全文。若有未知状态，保留在画面中。 |
| 0:45–1:10 | 切 PRD 与原型预览，展示编码只读、定位地址只读、详细地址可改；查看规则落实位置 | “PRD 和页面要表达同一个规则。来源版本有效只说明证据位置一致，业务解释仍需核对。” | 用真实控件操作，不用鼠标动画替代输入行为；标注所有模拟定位与编码。 |
| 1:10–1:35 | 展示基线验收缺项及截图，点击携带失败证据回会话；展示实际修订请求 | “原型能提交成功，不代表异常完整。这里缺少的是服务失败后的恢复路径。” | 原始基线确有此缺项。不得用合成成功报告冒充真实业务修订；录制会话不得曝光凭据。 |
| 1:35–2:20 | 展示修订后的实际版本。选择模拟服务失败，填合法值，提交出现失败，保留输入，再切成功重试；顺带展示字段修正后错误即时清除 | “失败可以复现，输入没有丢失，再次操作可以恢复；不是页面出现‘失败’两个字就算验收。” | 最终 HTML 已独立复验后录制；不改 HTML 来配合录像。生成过程可明确剪辑，不伪称几秒生成完成。PRD/对照另行审核，不把此交互通过解释成全部业务已正确。 |
| 2:20–2:45 | 查看新报告的时间、实际观察和截图，展开一条仍待确认的阶段规则 | “已执行的断言有证据；没有来源或阶段不明确的问题继续保留未知。” | 新稿 PRD 结论用章节、行号与摘录人工核对，不展示自动关键词评分。 |
| 2:45–3:00 | 展示版本变化使旧报告过期、用户确认必检范围及实际 ZIP 导出说明，结束在三份成果 | “交付的是哪个版本、验过什么、还有什么未确认，都可以回查。” | 使用隔离文件触发版本变化。必检 ZIP 明示网页资源清单与附件限制；不要宣称无绑定的通用 MCP 发布也已覆盖此门禁。 |

若真实运行等待较长，可以剪辑等待段并显示真实耗时；保留失败、待确认及版本变化的关键镜头。视频字幕优先用“实际断言满足预期”“版本有效/过期”“待人工确认”，避免“AI 已证明业务正确”。
