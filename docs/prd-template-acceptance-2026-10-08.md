# PRD 模板选择与结构验收

2026-10-11身份修复：模板原件与登记副本的回执冻结原字节，不是业务正文读取回执。`Service.refreshPrdTemplate`只复核明确模板的`current`版本、原字节hash、结构/解析版本，并在读取前后复核授权和解析路径；不为模板制造`textExtraction`，也不让模板进入业务`sourceReads`。真实业务DOCX仍要求宿主解析版本与全文hash。Plan仍不复制、不转换、不生成TXT、不冻结成果合同。原全量四项模板失败保留；修复后组合33/33及check退出0，日志`.test-data/production-template-init-repair-20261011/targeted-{1,2}.log`。当前统一1334/1334及check/build退出0，四项原模板失败均在当前全量实际通过；证据production-word-ui-root-integration-20261011/unified-result.json。下文历史验证仍按原时点保留。

本轮目标：把用户明确选择的模板接入现有任务验收和有限修正流程，避免只把模板当作普通参考正文。业务事实的准确性仍需单独验证。

## 使用入口

在输入框的“添加 → 引用资料”中，对 Word 或 Markdown 文件选择“用作 PRD 模板”。一轮任务只能选择一份模板，可以替换或移除；其他资料继续作为普通引用。与已输入的其他任务命令冲突时，由用户选择改用 PRD 或移除模板，不偷偷替换任务。

## 系统边界

- 模板由应用读取并冻结来源、版本、章节和可信表头，模型不能自行改写这份检查依据。
- Word 原件保持只读。Build 使用登记处理副本，优先复用可信提取结果；不为结构检查额外生成待应用 TXT。
- Plan 不创建处理副本。没有可用副本时明确标记模板结构未验证。
- 唯一普通 Markdown 成果可自动关联；多个候选成果必须明确选择。处理文件不作为交付 PRD。
- 按父章节检查缺章节、空章节和缺表头；允许合理标题层级偏移。模板示例的业务对象、状态和性能数字不成为硬性业务要求。
- 无法可靠识别的示例矩阵、明确不适用的章节保留未验证，不伪装成通过。
- 来源、处理副本、输出或解析器变化会使旧依据失效；修复复用现有有限重试，不另建 Agent 循环。
