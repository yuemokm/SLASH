# 按需工具已实现

Build 在 Pi 注册原55个宿主工具与加载入口，首次模型请求只显示17个常用工具与 `load_tool_group`。固定9组的名称、用途、工具名始终可见；模型等加载回执后的下一 Pi turn 使用新组。同一响应提前调用未激活工具仍报错，没有自动代执行或重放。Plan保持原只读集合。

加载只改变当前Run可见集合，原权限、取消、120次总工具预算及所有版本/来源检查继续执行。新Run和合法恢复从core重置；同Run已加载组保留，idle reload恢复集合并重施原压缩设置。没有修改模型、来源首包或压缩策略。

实施时核实旧SDK `excludeTools` 同时排除同名custom PowerShell，因此原55个定义不等于55个实际可调用工具。仅移除这项同名排除，实际registry断言definition就是原宿主受控PowerShell；初始仍隐藏，执行仍经过宿主日志与深层权限审批。另在既有repair拒绝名单补进程、PowerShell及外部提案三个名字，加载对应组也不能在自动修正阶段执行侧效。

验证使用真实生产createRuntime/Pi及本机HTTP fixture，包含下一turn schema、同batch拒绝、合法原工具回执、旧原型/业务/字段/摘要专项、恢复/reload、取消和生产Service修正/预算。它证明传输与宿主门禁，不证明云模型必然正确加载工具或实际节省token/耗时。静态工具JSON字符量与真实本地请求统计分开记录；没有字符换算token。

通俗说明：工具都在工具箱里，先打开常用工具，需要更多功能时再取对应的一组。取出工具不等于取得操作权限，检查和审批仍保持原样。
