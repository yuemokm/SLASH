## 独立发现

文档问题包括编码展示列解释错误、新建定位权限与后续变更权限混用、遗漏明确的负责人阶段规则，以及部分引用位置、范围和证据编号不准确。逐项原句和资料位置见 [最终独立质量结论](../.test-data/qe12-navigation-independent-review/FINAL-ONE-PAGE.md)。

同一终态 HTML 使用正式原型检查器，绑定实际草稿版本与哈希，未保存或更改模型的验收配置，也未将草稿先应用。浏览器确认两个错误：定位按钮生成的中文括号坐标不能通过自己的英文括号校验；重复提示后“仍要提交”会显示新建成功。72 个计划步骤中，67 通过、2 失败、3 因前序失败未执行。照片分类另有静态逻辑疑点，尚未实际操作验证。后端服务、完整业务语义和专业视觉保持未确认。

## 由真实证据确定的开发顺序

1. 修正 Agent 工具输入定义：可省略的宿主默认字段不应标记为模型必填，执行时继续严格解析。
2. 让原型定义/查询返回宿主核验的目标参数，明确验收规格 ID、任务输出 ID、成果 ID 的区别。待保存草稿可以直接验收；错误恢复不能要求先保存正式文件。
3. 精简模型接收的验收查询，将稳定文件身份与多次阅读证据区分。保留宿主完整记录和按需详情，不通过舍弃证据或放宽限额降低上下文。
4. 上述调用链稳定后，再针对明确的业务/交互反例验证原 Agent 的修正过程；旧失败作为基线保留，不能以重写测试标准消除失败。

前两项修复已完成：11 处工具输入定义统一采用输入模式，原型定义/查询返回宿主核验的 `target/runRequest`，错误编号和 pending 注册失败提供准确恢复说明。类型检查、45 项专项和正常构建通过；完整回归另以最终集成记录为准。新增本机 Pi 调用链使用明确的 HTTP/浏览器观察夹具，不算新的云模型或真实页面修复成功。第 3 项仅有审计设计，尚未实现。契约与边界见 [工具输入与草稿目标](prototype-tool-input-targets-2026-10-08.md)。

最终完整串行回归为 **664/664 通过**，零失败、取消、跳过；初次并发全量有一次图片测试 worker 原生异常，单文件和串行全量均未复现，原失败证据与未知原因仍保留。未因程序测试通过而改写本页真实业务/交互失败结论。
