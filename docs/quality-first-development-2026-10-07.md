## 重要实现决定

- 继续复用现有 QualityReport、PrototypeAcceptanceDomain、业务规则来源与处理回执、ChangeSet 和 Pi 会话。
- TaskAcceptanceDomain 提供薄的任务契约和报告层；自动检查状态与业务覆盖状态分开。候选要求可以自动起草，仅关键歧义或取舍才询问用户；无确定判定手段的内容保持待确认。
- 草稿预览通过授权的内存快照叠加同任务 pending 内容，不通过先保存到正式目录来凑验收。正式文件与旧草稿的证据不可互相冒充。
- 修复继续使用同一 Pi 会话和原授权，最多两轮，受原 Run 总时间、工具预算和取消信号约束。出现未知外部效果不能自动重放。
- 原型验证覆盖运行硬错误、具体业务交互与截图质量；没有视觉能力的模型不伪称已经看图。PRD文本检查不能替代逻辑审核。
- 模型不能自行删除用户原始要求、弱化已锁定标准、移除回归基线，或直接写入检查通过。需要修订预期时保留来源、版本和明确理由。
- 本地保存与外部交付分开：用户可显式保存尚未验证的草稿，但保存不会提升验收状态；发布仍走既有门禁和操作回执。
- 不为本次增加多 Agent 市场、额外供应商或复杂团队配置。不改变现有启动BAT，不制作便携版。用户后续明确要求优先修复全局技能安装，因此该项已纳入本轮；全局指Slash各项目共享，不读取或改变Codex的技能配置。
