# 12-Factor Agents 对照与本轮开发取舍

日期2026-10-10。用户明确要求在继续待办前先阅读。已阅读README、12项正文与预取上下文附录；固定官方仓库commit `d20c728368bf9c189d6d7aab704744decb6ec0cc`，参考副本 `.test-data/12-factor-agents-reference-20261010/`。这是工程经验指南及示例，不是可直接替换Slash/Pi的完整执行器。项目声明内容/图片CC BY-SA 4.0、代码Apache-2.0；本记录为结合本仓库的独立判断，不复制示例实现或图片。

## 最直接的采用点

- **小而聚焦（10）**：把验收分成PRD跨表维度、原型局部交互、视觉及最终组合回归。每段输出、源版本和验收标准明确，但全部原要求仍需最终核对。原稿手工改进只能证明交付稿改善，不能冒充Slash云模型自动完成。
- **掌握上下文和提示（2、3、附录13）**：优先带入已授权、已核验的任务明确引用资料，减少重复定位；保留全文来源和偏移。已有表格选段、跨表候选、nextInput、提示身份和恢复去重均继续复用。不能把“预取”理解为把所有授权目录全文塞入请求，更不能把资料放进可信系统权限层。
- **结构化意图与控制流（1、4、8）**：模型选工具，宿主校验schema、权限、版本、顺序与外部副作用。当前三项harness修复正补这一层；不依靠提示词要求模型记住取消或串行。
- **可操作错误（9）**：保留错误类别、实际目标、允许的下一步；可纠正输入交回Pi，致命错误及外部未知结果停止。本轮不套用统一“三次必停”，既有两轮交付修正和总预算保留；连续同错若需单独熔断，先有实际证据再设计，避免截断合法探索。
- **统一可信状态（5、6、12）**：统一的是事实来源和状态转移规则。工具已提交与Run随后取消是不同事实；业务验收又是另一维度，不能折叠为一个成功值。已有SQLite操作/检查点/外部回执为事实，Pi历史为模型上下文，UI为投影；不能把权限、凭据或外部未知结果仅托付给会被压缩的聊天历史。崩溃后的未知执行仍应核对，不能因示例可回放就重放写入。

## 已有能力与暂不扩展

| 因子 | Slash现状/本轮处理 |
| --- | --- |
| 1、4 | TypeBox/Zod工具契约与网关已在main/agent.ts、capability-broker等实现；保留真实回执 |
| 2、3 | 系统提示快照、content-review输入身份、表格选段、Pi原生压缩已有；本轮验证实际送入资料而非重建压缩 |
| 5、6 | Store/Service/检查点与运行输入队列已有；补工具终态保护，不伪装完全durable的任意点暂停恢复 |
| 7 | 既有审批、Plan反馈、输入队列继续使用；普通工程选择自行完成，仅缺业务信息/权限时问用户 |
| 8、9 | 本轮错误分类、致命中止、未知结果核对、写工具执行声明及相关真实Pi测试 |
| 10 | 当前只读子代理继续复用pi-subagents；主任务以小验收单元推进，不另建多Agent框架 |
| 11 | 当前个人桌面产品不新增邮件/Slack入口、自动通知或定时任务 |
| 12 | 借鉴显式输入→决策→效果→持久结果的可测边界，不改造成无持久数据的应用 |
| 附录13 | 预取确定所需且已授权的有限资料，哈希/来源/权限继续复核 |

## 随后执行顺序

1. 收尾已经实现的三项可靠性改进，真实Pi本机HTTP与Service状态联合回归，根代理统一构建。
2. 独立新profile，用同任务先前授权的模型配置完成一次新版PRD审查；输入从冻结快照经当前构建器重建，记录来源覆盖、真实响应与限制，不重复已经正确的两行改稿。用户本轮已取消旧额度保留限制。
3. SFA保留原件，先完成离线新交付稿和局部错误修复，再按同版本做关键路径、截图及状态验收；自动云生成质量与人工/子代理制作的文件分别记录。
4. 开发启动删除重复生产renderer构建，已有真实BAT和无生产renderer首次启动证据继续保留；不以此宣称全部启动延迟根因已解决。
