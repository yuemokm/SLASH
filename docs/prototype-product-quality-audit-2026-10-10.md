# 原型产品质量审查与 Agent 改进目标

用户在2026-10-10明确指出当前原型缺乏设计感和实际使用价值，要求先评价，再改进Agent，使生成原型达到可用以上。本记录优先于此前“七项局部界面目标通过”的狭窄结论；已有行为回归、版本和交付证据仍保留。

随后用户明确要求原型内不显示与产品无关的制作提示，包括演示、非实际产品、后台/接口限制等。新版页面只保留业务内容和正常操作反馈，实现限制与来源核对移到Slash交付说明或独立记录。旧回归中强制模拟文案、技术说明折叠区域的断言必须按这项明确变更建立新版；保留旧套件和差异原因，不宣称删改后的套件仍是旧23/202。

## 当前结论

当前稿是可运行的业务演示，但尚不足以作为成熟、好用的产品原型交付。主要问题是任务组织和信息层级，不只是颜色或圆角。它面向业务员新建门店，应优先支持快速录入、清楚的反馈和补充信息填写；不应套营销落地页，也不应机械套列表工作台。

审查对象为已隔离导出的 `bae4d668d9de3ba3edadda219c48184f4bc370d5b204ae9f006ae3731017d016` 版本。根代理通过Codex内置浏览器，在本机只读HTTP预览中实际操作；没有真实后台、真实定位或外部写入。新证据目录 `.test-data/prototype-product-audit-20261010`。主代理评判不等于用户认可或无障碍认证。

## 最小 Agent 改进

先完成Pi生态复用核查，见[调研记录](../exa-results/pi-prototype-design-reuse-audit-2026-10-10.md)。继续使用现有Pi、已实际加载的frontend-design技能、隔离浏览器和版本绑定回执；不新增框架、固定风格或强制人工审批。

1. 制作前给出简短、可观察的设计判断：使用者、主要任务、必要输入、主要动作、完成反馈、信息分组与目标终端。区分表单、工作台和消费端体验；区分整体设计与精确局部修改。
2. 制作后实际执行正常流程和错误恢复，检查初始、任务中、结束/异常状态。业务回归保持，不能用自动滚动后点击成功替代操作可发现性。
3. 图审继续绑定真实截图和当前版本，补充对主任务、视觉层级、密度与说明负担的检查。只判断所见，不能根据截图推断键盘或交互成功；没有问题不等于通过。
4. 既有有限修稿在用户范围内调整必要分区，保持业务字段、规则与数据；制作注释依最新要求外移，实际交付报告继续诚实说明模拟范围。旧视觉规则的回执保留历史，不作为新规则的当前修稿依据。

## 本轮验收标准

不以武断的综合分数掩盖缺口。改进稿需要同时满足：业务回归不退化；主任务及主要动作易找到；补充信息填写后能方便提交；桌面和手机信息密度合理、选项可读；错误恢复与必要键盘焦点明确；页面没有无关制作注释，实际交付记录明确实现限制。字体、色彩、间距与控件状态需要一致，但不强制某种审美风格。

必须用修改后的真实Agent产生新稿，再以相同任务/视口对照当前稿。代码检查只能证明实现没有已知回归，不能证明设计质量提高。旧稿和真实失败记录全部保留；新质量结论目前仍待验证。
