## 工作流约束

- 六类工作流为可选的会话意图，不强迫普通对话选择流程。
- 原型与 PRD 可从描述开始；研究允许通过已授权工具联网。会议整理和原型转 PRD 要求相应的真实输入资料。
- 文件来源包含挂载、相对路径、可选成果身份、版本和预期哈希。执行时复核目录授权、权限策略和当前内容。
- Run 记录来源回执与截断，不重复持久化大段源文。引用内容是资料，不能授予工具或目录权限。
- Plan 只读研究，确认后 Build 才能生成修改草稿。恢复/确认携带来源版本，更改后的资料不能静默当作原方案依据。
- 变更说明基于同一文件两个真实版本的确定性差异。模型只解释改动与待确认影响，不能捏造实际差异。
- 点选原型元素和文档选段、局部修改、版本查看/恢复继续使用现有实现。

## 协同架构

```mermaid
flowchart LR
  User[产品经理] --> Chat[会话：描述 / 引用 / 工作流]
  Chat --> Plan[Plan 研究与方案确认]
  Chat --> Build[Build 执行]
  Plan -->|用户确认| Build
  Sources[项目资料与成果版本] --> Read[授权读取与来源回执]
  Read --> Plan
  Read --> Build
  Build --> Pi[Pi Agent 与受控工具网关]
  Pi --> Draft[草稿 / ChangeSet]
  Draft --> Check[适用的静态检查与问题提示]
  Check --> Confirm[用户核对 / 应用修改]
  Confirm --> Version[成果版本 / 确定性差异]
  Version --> Preview[交互预览 / 文档阅读 / 局部引用]
  Preview --> Chat
  Version --> Deliver[本地导出 / CLI 或 MCP 交付]
  Deliver --> Receipt[版本绑定回执 / 未知结果待核对]
  Decisions[待确认事项与处理历史] <--> Chat
  Decisions <--> Check
  Settings[模型 / 连接 / 权限 / 高级参数] --> Pi
```

没有新增 Agent harness、独立数据库或强制团队流程。Electron/Pi/SQLite/文件版本体系延续。Agent 仍在主进程运行、预览仍为受限 iframe，不能把本轮减重宣称为已实现独立进程沙箱。
