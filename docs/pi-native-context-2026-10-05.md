# Pi 原生上下文与模型能力配置

日期：2026-10-05。版本：0.3.7，源码、214项测试、开发与打包GUI和便携版启动验收完成。本记录覆盖 0.3.6 中由 Slash 主动估算、压缩和拦截上下文的调度设计；参考原件保护与任务状态修复继续保留。

## 已确认方向

1. Pi 负责上下文占用计算、自动压缩、摘要、近期历史保留以及溢出后的有界恢复；Slash 不维护第二套压缩调度或固定最小输出预算拦截。
2. 正确传入模型的上下文窗口与最大输出限额。完整端点、协议和模型 ID 匹配 Pi 目录才采用目录能力；代理同名模型不视为官方模型。上游仅接受身份匹配、数值合法的明确元数据。用户可手动覆盖，并可清除覆盖恢复自动选择。
3. Slash 继续依据本次 prompt 的真实响应事件判断任务是否完成，防止 Pi 恢复时移除内存中的截断消息后误用上轮成功状态。
4. Slash 继续管理任务资料选择、引用来源、权限、参考原件保护、副本处理、成果草稿和外部操作记录。

## 模型能力的来源与兼容

优先级为用户明确覆盖、可信上游能力快照、精确匹配的 Pi 模型目录。上游没有提供元数据不代表能力为零，也不代表模型不可用。

无法识别的旧模型保留兼容限额，必须显示未验证及可修改入口，不把兼容数值称为真实上游上限。新自定义模型同样允许明确配置；能力刷新不能静默删除覆盖或改变已有密钥、协议和思考设置。数值必须是合理范围的正整数，最大输出小于上下文窗口。

能力查询按需执行并缓存，正常任务不新增一轮上游模型查询。任务、模型连接检查和视觉等运行入口应使用一致的模型能力解析，实际请求的较小测试输出预算仍由调用场景自行指定。

元数据字段依据：[Anthropic Models API](https://platform.claude.com/docs/en/api/models/retrieve) 将 `max_input_tokens` 定义为输入上下文窗口上限，`max_tokens` 定义为请求输出参数上限。通用兼容端点不保证提供这些字段，缺失或无效时保留未验证状态，不能从模型名称猜测限额。

## 协作边界

Pi 的会话历史与压缩边界是上下文恢复的依据。Slash 订阅压缩开始、结束及失败事件用于显示，不因为正在压缩就新建另一轮任务。取消仍传到当前 Pi session；恢复失败保留已有草稿、部分回复与操作检查点，不自动重放用户真实项目任务。

资料按需读取与输出截断是不同职责。保持当前工作流的文件大小、引用字符上限及来源回执；非文本处理副本只提供已核验元数据，不能声称已读取其正文。参考文件只读保护不因移除上下文拦截而放宽。

## 使用入口

设置 → 模型 → 编辑模型 → 高级：模型容量。两个输入留空使用自动结果，填写为明确覆盖；“恢复自动值”清空覆盖，点击“保存模型”后生效。重新检测会按需查询配置的供应商，失败保留既有有效快照。无需密钥即可查看本地Pi目录信息，实际模型执行仍要求凭据。

更新涉及Electron主进程，须退出旧应用并重启 `npm run dev` 或新便携版，仅刷新页面不会更新运行层。

## 0.3.11：小窗口的原生近期保留配置

后续真实修订 NiJUFi 达到压缩阈值，但原生默认保留 20000 tokens 时无可摘要前缀，输出被原生适配器缩减到 1819 后截断。通过公开 SettingsManager，在 session 初始化完成后、且未显式配置近期保留量时采用 `min(Pi 默认值, floor(contextWindow/8))`：当前 65536 兼容窗口保留 8192，200000 窗口仍保留 20000。用户配置、模型容量、预留量和恢复次数均不变，不写用户设置文件。

切分、摘要、自动恢复仍由 Pi 执行。实际历史分支及本地假供应商的真实 Pi 循环已验证该设置生效；新云任务也已出现原生阈值压缩成功事件，最终业务修订与终态另见 [修改闭环记录](pm-revision-loop-2026-10-05.md)。实现与测试边界见 [原生配置适配](draft-edit-2026-10-05.md)。
