# 设置与 Agent 能力修订

日期：2026-09-21。依据用户四张测试截图。本文件是本次实施与验收的设计输入，实际通过的检查另记 implementation-status.md。

## 问题与决定

现有实现接入 Pi SDK 会话循环，但关闭其内置工具，仅提供部分自定义业务工具。因此网页、终端、安装和连接配置缺失属于产品实现缺口。继续使用 Pi SDK，通过自定义工具实现与现有文件版本、目录权限、操作记录一致的能力接口。

用户进一步要求优先复用 Pi 的成熟源码能力。工程默认使用 Pi 发布包的公开 SDK/工具工厂，复用上游实现；确有公开接口无法满足的需求时再考虑维护源码补丁或 fork。不能以“SDK 接入”为理由重新实现所有通用工具，也不能为快速恢复能力而绕过应用权限。当前已安装版本提供 `createPowerShellToolDefinition`、`createReadTool`、`createGrepTool` 等公开入口；具体接入与差异需按实现验证，不把整个仓库未使用的功能列为已交付。

## 协同与状态

设置 UI 和 Agent 都调用主进程业务接口。模型不得直接更改权限策略；参考文件的指令也不能提升权限。连接配置经策略确认后写入同一注册表，并发出状态事件，连接页据此刷新。

权限确认与业务结果分开记录：用户批准不等于命令成功；进程超时或取消可能已产生部分修改，不能标记成“没有发生”，不自动重试有副作用的操作。文件草稿仍执行原有真实路径授权、版本检查和冲突保护。

终端不是操作系统沙箱。允许终端工具意味着代码可使用当前 Windows 身份的权限；界面必须说明这一边界。不能将工作目录、命令 allowlist 或 shell:false 称为完整沙箱。敏感凭据不得出现在列表、模型上下文、操作日志或分发包中。

共享创建仍依赖 Windows 管理员授权，盘符连接仍在普通用户会话内进行。自动填充不改变 SMB 身份和 ACL 语义；不启用 Guest、不默认 Everyone、不把未知账号编造成可用凭据。

## 实施边界

本次重点是实际常用工具、设置与易用性；不以本次改动宣称 F01—F19 全量完成。双机 SMB、真实飞书/钉钉写入及实际 MCP 发布必须分别保留真实验证，缺少设备或目标时明确未验证。
