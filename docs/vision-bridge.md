# Slash 视觉辅助桥接

Slash 的视觉辅助采用“原生视觉优先，辅助模型兜底”的策略。模型条目继续保存文本模型的连接信息，工作区偏好额外保存 `visionModelId` 和 `visionAutoFallback`。用户可以在设置的“模型”中选择一个支持图片输入的模型，并声明其兼容协议。

会话支持粘贴或拖入 PNG、JPEG、WEBP、GIF。图片先由主进程复制为工作空间隔离的不可变附件快照（12 MB 上限、magic byte/尺寸校验和 SHA-256 校验），会话只持久化附件 ID。支持图片输入的模型通过 Pi 的 `session.prompt(text, { images })` 接收原图；文本模型则由 VisionBridge 调用已标记的视觉模型，返回统一结构化证据（摘要、OCR、版面、语义、视觉线索和不确定性），再以不可信证据标记附加到当前会话上下文。当前支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 三种兼容协议；相同图片、模型、端点和提示会使用带 TTL/LRU 的本地哈希缓存。这样即使主模型是纯文本模型，仍能完成截图、原型、流程图和调研图片分析。

## 安全边界

- 只接受用户通过粘贴或拖放明确选中的图片路径，并在发送前复制成工作空间隔离的附件快照。
- 主进程限制图片类型和 12 MB 大小，不把任意文件当作图片发送。
- 图片内容不会自动写入成果，也不会自动提升工具权限。
- 视觉模型失败时任务失败并显示原因，不把未验证的模型输出标记为事实；自动回退只选择用户明确标记为支持图片的模型。
- 视觉证据使用 `<untrusted_image_evidence>` 标记，原始用户任务、附件元数据和证据文本一起保存在 Message/Run 上，便于在会话和交付前检查中追溯。

## 与 ModLens 的关系

ModLens 的关键设计是：当主模型没有视觉能力时，把图片交给独立视觉引擎，再返回 OCR、版面、语义和不确定性证据；同时保留模型能力判断和可配置的多引擎回退链。Slash 已实现本地桌面端闭环：可配置视觉模型、拖放/粘贴、结构化证据、协议适配、本地缓存和主会话注入。后续可以在连接管理中加入视觉模型健康检查、CLI 复用和更细的 OCR/图表能力声明。

## 后续扩展

1. 将图片哈希和视觉证据提升为可查看的成果来源版本，支持同一图片追问时复用和失效。
2. 增加视觉模型能力声明，区分原生视觉、OCR、图表和 UI 理解能力。
3. 引入多个视觉引擎的健康检查、顺序回退和失败冷却。
4. 在原型质量检查中增加截图与 HTML 页面结构的对照检查。
