# 原型截图审查：保留初始和最新用户要求

2026-10-09。用户要求改善 Slash 自动生成原型的比例、布局与视觉；这次产品修改只修已有截图审查的信息丢失，不把手工 SFA 副本当作生成质量已经改善。

## 已证明的问题与范围

`visualReviewInput` 原先对用户要求数组 JSON 直接取前 6000 字符。本地定向探针调用真实产品函数、使用已有正式截图身份和合成要求：10134 字符的长背景加最新 390px / 主要操作优先的修改要求，旧输入完全缺失最新要求，并留下不完整的 JSON 字符串。没有云调用。

证据：`.test-data/actual-sfa-layout-20261009/review-context-probe.json`。修改后同一探针输出 `review-context-probe-after.json`：3168 字符的完整 JSON，初始背景与最新要求均存在。探针证明选择函数行为，**不证明实际 SFA 当时的用户输入超过预算**。

另一探针证明普通同会话后续 Run 的验收契约只包含本轮输入，只有明确恢复才继承原契约。但普通后续输入也可能是新任务，本次没有全量继承旧任务、修改 service 契约或重建上下文系统。实际关联证据未齐前不能把此行为认定为本稿根因。

## 实现

owner：`main/prototype-visual-review.ts`、`tests/prototype-visual-review.test.ts`；service 的旧“仅前6000字符”覆盖提示由模型/集成 owner 协调更新。复用原接口与 coverageLimits，未新增持久 schema。

- 预算仍为 6000 字符，按序保留初始要求与最新要求；剩余空间从最近的中间要求向前选取。
- 超长单条保留头尾，记录每条 `omittedCharacters`；未选要求以逐条零基索引 `omittedRequestIndexes` 列出。不截断 JSON，不悄悄声称全量覆盖。
- 有删节时在既有视觉回执 coverageLimits 标明条数；没有改变视觉能力门槛、三图 / 12 MiB、独立超时、两轮回修上限或“不裁定验收通过”的边界。
- inputHash 绑定完整要求哈希、选择版本和所选文字；未展示正文发生变化也生成不同输入身份，readAt 变化仍不改变身份。

契约已有上限：100 条、单条 10 万字符、总正文 50 万字符、ID 200 字符。省略索引最多 100 个整数，不能独占预算。空正文余量不再额外插入截断标记。

## 检查与未完成

`npx tsx --test tests/prototype-visual-review.test.ts`：15/15；新增长背景与末尾要求、初始/最近优先、省略正文变化失效、短输入完整、单条头尾、转义字符、真实最大契约输入和回执覆盖提示检查。`npx tsc -p tsconfig.node.json --noEmit` 通过。无云模型调用、Computer Use、build、dist 写入、CSP 放宽或用户原稿改写。

现有 `PROTOTYPE_GUIDANCE` 已要求任务优先、信息密度、层级、token、按需读取设计规范及真实截图；因此不再追加同义美学提示。技能发现不等于加载，加载 SKILL 不等于读取其引用规范，独立只读图审也不会自动继承生成会话中读过的全部 skill。实际 SFA 的精确回执另行核对；旧历史 frontend-design 已加载而未看图的结论不能套成本次事实。

仍未完成：用户实际 SFA 的视觉设计改善与完整交互验收、自动生成同版本新稿的实际图审效果。此修复是避免“用户刚说的布局要求没交给审查者”，不是保证任何风格自动合格。

通俗说：长任务以前只让审查者读开头，最后补充的排版意见可能根本没看到。现在会保留开头和最近意见，并明确哪些内容没看全；页面本身是否好看仍要看实际结果。
