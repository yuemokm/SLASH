## 真实问题

[真实视觉修订](qe12-real-visual-local-result-2026-10-08.md)已完整加载 frontend-design 并读取原 HTML，但没有产出新版。第一条编辑缺少替换参数，在官方日志之前被拒绝；Pi 已收到错误，不能称它没有反馈。第二条合法调用有 21 项替换，第八项漏抄原容器的标识，Pi 正确拒绝整批。其余项不得偷偷应用，也不得忽略属性使其通过。

## 最小设计

1. 编辑工具公开 schema 明确要求一组 oldText/newText 或 edits，不能混用；沿用原字段、限额和严格校验。
2. 只观察 read_draft / edit_draft 的 Pi 实际执行事件。输入不合法时，在本 Run 正式操作中记录一次安全失败，并计入原工具预算。合法调用继续走原网关记录，不重复计数。
3. 拒绝记录不执行工具、不读文件、不触发写入审批；不记录原始参数、替换正文、未知字段或秘密。取消/结束后的事件不能恢复任务或创建审批。
4. 对 Pi 已知的找不到旧文本和匹配不唯一错误，返回稳定错误代码、真实目标、失败项、当前哈希与草稿 ID，并建议使用有界 read_draft 重新读取后提交小批修改。无可靠定位则明确未知；不编造行号或重写原文。其余原生错误继续保持原有语义。
5. 精确/原生模糊匹配、唯一性、批次原子性、原件只读、Plan、撤权、取消、版本核对均保持。
6. 失败记录即时进入现有检查点；对话的折叠执行记录展示草稿读取/编辑失败的可读原因，不能过滤掉失败或标为完成。沿用原布局，不增加独立日志页面。

## 实现边界

- `shared/draft-edit.ts`：编辑参数公开为单项和批量两个互斥分支；宿主仍严格拒绝不合法参数。根对象类型明确为 object。本次真实 Pi 本机请求验证的是 `strict: false` 的兼容路径，没有认证所有供应商或严格 Structured Outputs；[OpenAI 官方严格模式规范](https://developers.openai.com/api/docs/guides/structured-outputs)对根 anyOf 另有限制，不能据此宣称全协议支持。
- `main/draft-input-rejections.ts`、`main/agent.ts`：观察原生开始/结束事件并确认实际 schema 拒绝，缓存安全分类及调用 ID 哈希；成功、取消与结束均清理待记录状态。未知、重复、晚到事件不产生重复操作，不保存原始参数或错误正文。
- `main/service.ts`：在原 Run 内保存失败和检查点，计入原 120 次工具调用限制；不执行能力请求、文件操作或审批。完成后的回调不能重开任务。
- `main/draft-edit.ts`：仅将 Pi 已知匹配缺失/不唯一错误转成有界恢复信息；失败后复核版本、权限和取消，优先保留真实冲突原因。既有编辑器与原子提交不变。
- `src/run-operation-view.ts`、`src/App.tsx`：原折叠执行记录增加草稿失败/取消的可读原因；只取已知分类和有界索引，不展示原始 JSON、正文或目标路径，不将失败标成成功。

## 验收要求

- 缺替换参数、混用参数及未知字段不会执行文件操作或产生审批；正式记录一次。
- 真实 21 项/第八项不匹配形状仍零草稿，反馈不泄漏替换正文或虚拟路径；重新读取并进行正确的小批修改可产生待应用草稿，原件不变。
- 原生模糊匹配及 BOM/CRLF 仍有效；取消、Plan、原件、撤权与版本保护不退化。
- 同一工具调用不重复记账，预算不扩张，任务结束后的通知不改变终态。
- 参数拒绝与匹配失败出现在本回复的执行记录；失败状态、取消状态和成功状态分别显示，正文和原始 JSON 不直接进入提示。
- 本机固定响应只能证明软件链路；不能代替云模型、真实视觉和业务质量验收。

通俗说：先让软件准确告诉模型“这次没改成、哪一项失败、该重新读哪里”，同时让用户看见真实失败。它能改善修稿恢复，但不会直接把旧原型变漂亮。
