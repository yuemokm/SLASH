# 第一阶段运行时能力

版本：v0.1 · 2026-09-26

第一阶段把 Slash 的会话执行升级为可观察、可恢复的 Run。聊天消息仍是用户入口，Run 负责记录一次实际执行；Pi 会话负责模型上下文，Slash 业务状态负责任务生命周期、权限、草稿和外部副作用。

## 已实现

- Run 具有稳定状态和阶段：排队、准备资料、启动模型、生成与执行、调用工具、等待授权、检查成果、完成、取消、中断和失败。
- 每个 Run 保存启发式任务计划。计划包含理解目标、检索授权资料、按任务类型生成或修改成果、检查变更和交付条件。
- Run 持久化 `startedAt`、`updatedAt`、`finishedAt`、`attempt`、`resumable` 和错误原因；状态变化通过应用状态事件刷新界面。
- 应用重启时，未完成的 Run 标记为 `interrupted`，保留草稿、工具记录和已经持久化的部分回复，不自动重放工具或外部写入。
- 中断或模型失败的 Run 可在会话或“任务与回执”设置中继续。继续会创建新的 attempt，并带上来源 Run 引用；存在结果待核对的外部操作时禁止盲目继续。
- 会话内显示任务计划卡、当前阶段、尝试次数、最近更新时间、错误原因和继续入口；底层工具参数仍默认折叠。

## 运行边界

- 计划是执行摘要和用户可理解的工作步骤，不是模型内部思考内容。
- 任务成功必须经过模型响应检查；成果草稿应用和外部发布仍有各自的 ChangeSet、权限和回执流程。
- 取消任务只阻止后续派发并尝试中止当前运行，不撤销已经完成的本地提交或远端副作用。
- 恢复任务前会检查同一 Run 是否存在 `outcome_unknown` 外部操作，避免重复创建或发布。

## 验收证据

- `tests/runtime.test.ts` 覆盖计划保存、阶段时间线、成功完成计划、中断/失败继续任务、启动取消、工具预算、Plan 无工具调用和权限模式矩阵。
- `npm run check`、`npm test`、`npm run build` 已通过；当前测试共 75 项。

## 下一步

### Plan / Build 与运行权限（2026-09-26）

Plan 是独立的 Run 模式。它允许 Pi 会话使用只读资料、知识库和网页工具，但服务网关拒绝写入、执行、连接配置和外部发布；只读工具结果仍受授权目录、网络和权限策略约束。模型生成的方案选项和摘要持久化在 Run 的 `proposal` 中，Run 进入 `awaiting_plan`，不会伪装成等待工具授权。

用户可以勾选模型实际生成的方案、在下方编辑自定义执行内容并确认。确认内容按选择顺序与自定义文本拼接后原样保存为 `approvedInput`，创建关联的 Build Run；重复确认返回同一个 Build Run。生成失败没有可确认 proposal。

Build Run 保存模式、权限模式、模型条目和来源 Plan Run 快照。`standard` 沿用能力设置，`accept_edits` 自动允许成果编辑，`full_access` 自动允许未明确禁止的能力；全局 deny 始终优先，模式不提升 Windows 身份、绕过路径校验、版本检查或结果核对。运行中撤销 deny 会终止等待授权或阻止后续派发。

后续阶段继续补充 ContextManifest 的来源卡片、Run 与真实事件序列的补读、确定性成果验证、ChangeSet 多文件检查清单和外部结果核对界面。Plan 的方案编辑与确认已经作为独立交互提供；后续可继续增强方案结构化解析和来源卡片。
