# Pi 原生上下文与 billion-context 对照验收

2026-10-08。本记录负责现有机制、问题归因与同材料验收；固定 `billion-context@0.1.188` 的代理/API 实跑由辅助包代理另记。本记录未改运行底座、未读模型密钥、未调用云服务，也未把协议夹具当作真实模型效果。

## 当前事实与决定边界

**本轮决定：暂不替换 Slash 默认上下文方案。** 这不是判定 billion-context 不稳定：固定 0.1.188 的真实本机代理基础检查已通过，且重试可用公开配置关闭。但没有真实模型、同一 PM 任务的语义/完整成本优势证据，Slash 的受控还原读取、项目授权、请求预算及退回原生还未接入验证。因此不满足用户“效果和稳定性同时达标再替换”的条件。保留候选和可复跑测试，不修改现有会话数据或默认路由。

本次比较对象是 Slash 当前 Pi `0.86.1` 与 `billion-context@0.1.188` 的受控代理方案。`billion-context-pi@0.1.83` 是另一种会取消 Pi 原生压缩的进程内扩展，不混在同一实验。保留当前用户明确模型窗口、输出限额、思考配置和凭据；不能用更大窗口或更多调用包装成压缩改善。许可补充：core 发布物 LICENSE 除 MIT 还要求产品可见的 billion-context/acp-kernel 署名；采用前必须落实，不能只记 MIT。固定包路径及许可复核见 [上下文与记忆审计](pi-context-memory-selection-2026-10-08.md)。

## Slash 实际原生机制

依据 `main/agent.ts`、`main/session-compaction.ts`、已安装固定 Pi 的 `dist/core/agent-session.js` 与 `dist/core/compaction/compaction.js`，不是只按README推测：

- SettingsManager/AgentSession 负责估算、切点、摘要、原会话保存与压缩恢复。Slash 没有第二个主动 compact 调度器。摘要通过同一显式模型和凭据发送，额外摘要调用有实际 token/耗时成本。
- 原生默认开启，`reserveTokens=16384`、默认 `keepRecentTokens=20000`。Slash 只在用户没有普通或当前模型 keepRecent 明确配置时，内存设为 `min(当前默认, floor(contextWindow/8))`：65536 窗口为8192，200000窗口仍为20000；不改模型真实容量、不改reserve、不保存用户配置。
- 原生阈值是估算上下文 `> contextWindow-reserveTokens`。prepareCompaction 无可摘要前缀/无有效保留边界时可返回空，并非达到阈值就必然压缩。它保留近期消息，将较早历史和必要的回合前缀汇总；前次summary及文件操作也参与处理。
- 对可恢复的 length 或上下文溢出，Pi 最多一次 compact-and-retry；不是任意 length 都能恢复，也不保证超长工具参数最终完成。摘要本身 length 被拒绝为不完整，失败不应伪造摘要。503等一般重试另按原生设置，Slash不再外套循环。
- 会话内持久记录compaction，并继续保留原历史可审计。Slash订阅真实compaction事件与当轮message_end，避免用之前成功stop覆盖本轮失败。取消同时触发session.abort和公开preflightResult守卫，防止“摘要取消后却继续发新任务”。
- 权限、来源版本、参考原件只读、ChangeSet、父Run120次总工具预算及截止时间归Slash宿主；更换压缩不能绕过这些边界。独立content_review与只读子任务是其他显式模型调用，不等于主会话压缩。

运行机制已由 `tests/runtime-context.test.ts` 的真实Pi+本机HTTP fixture覆盖：threshold持久摘要、length恢复成功及一次后终止、摘要失败、503重试、取消摘要后不发新任务、保留原生默认及不写用户设置。它用固定摘要字符串验证状态机，**没有证明摘要语义质量**。历史与版本说明见 [原生上下文记录](pi-native-context-2026-10-05.md)。

本轮实际复跑 `node node_modules/tsx/dist/cli.mjs --test tests/runtime-context.test.ts`，10/10通过，4.847秒；仅本机HTTP，无云。合成素材JSON已解析核对，但尚未据此声称两臂语义A/B通过。

## 极小同材料 A/B

复用 `tests/fixtures/context-pm-material.json`：8条短历史，来源/草稿版本、F/P独立维度、编码/名称否、来源许可缺值unknown、仅两行增量修订、其他文件禁止修改。素材全部合成，**expected只供外部断言，不能作为请求内容；finalQuery使用原文，不附带字段正确值**。

两臂采用同一原始history、system、tool schemas、最后问题、模型/端点/思考/输出预算；A为现生产原生配置，B为受控core代理并明确唯一压缩所有者。不能让A重复摘要而B无摘要，或两臂不同历史。小窗或高usage触发仅标记“强制压缩机制试验”，不是供应商容量的测量。

只做三个短场景，不新建benchmark平台：

1. **无压力对照**：短history不触发压缩。两臂关键材料、toolCall ID/参数/结果对应、返回stopReason/usage等保持。代理无必要改写即为协议回归；本场景不证明压缩收益。
2. **一次压缩后的业务保持**：将无关背景放在历史间隙，关键材料分别置于早期、中间、较近处；确保真正压缩掉承载关键材料的历史，而不是只删重复填充。若强制测试输入规模，在A/B使用相同padding，保存输入hash与触发条件。最后提问不重复答案。逐项核SOURCE-V1/DRAFT-V3、经纬度与定位地址F=false/P=true、详细地址F=true/P=true、编码/名称P=false、数据来源unknown、仅两行/8列、不改HTML/原件/后文、不添流程及未应用未验收。至少再交换关键材料位置一次，避免单一“针”总在保留尾部。
3. **压缩中取消及重开**：中止正在等待的压缩/代理请求，确认无后续上游请求、无工具执行、无落盘草稿，子进程结束；用同会话重开，原始历史与持久摘要可正确识别，不把失败partial当成成功summary，不自动重放外部操作。两项目同材料不同标记检查无串话；代理状态与监听地址不能跨项目复用。

本地固定HTTP回复适合证明真实Pi状态机、代理压缩分支、资料是否仍在最终payload以及取消/恢复。若假摘要无条件返回正确事实，或假模型看到什么都返回expected，结果是循环论证。可让fixture仅从**实际收到**材料提取可识别事实，缺失立即unknown/失败；这能检出资料丢失、证明某条具体保留路径，但仍不能证明真实模型理解或泛化优于A。B若用可恢复索引，恢复调用必须真实可用、权限/预算计入，不能只给模型不可访问的引用占位符。

## 需要记录的成本

每次完整场景保存一份小回执即可：原始材料hash、有效压缩配置、触发原因、实际请求次数及类别（摘要/主任务/检索/审查）、压缩开始结束/总墙钟耗时、最终结果、取消与恢复终态。不得只截取B较短的最后一次请求。

- **Tokens**：按两臂所有实际模型调用累加输入、输出、cacheRead、cacheWrite，分别报告，不把缓存读token又重复加入已含缓存的input。费用按实际供应商计费语义另算，不用token简单相加冒充价格。fixture自己返回的usage是合成值，不能作为实测节省；本地tokenizer估算也必须注明与实际模型tokenizer未核实。无法取得可靠usage时记录UTF-8字节/字符和估计token，结论限于请求体体积。
- **耗时**：压缩额外耗时、首个有效工具/正文时间、完整任务耗时分别比较；至少成对执行且交换顺序，保留所有失败。loopback网络固定延迟适合机制开销；不能外推真实供应商节省百分比。
- **质量**：关键字段和修改边界全部通过，unknown不被补成yes/no；保留有效来源定位/版本。不以最终JSON结构合法、代理200、自动检查零问题替代业务事实正确。

## 切换准入

用户补充要求：替换同时考虑稳定性。下面均为硬门槛，不能用压缩倍率或一次成功抵消；尚未运行的项目统一记为“未验证”，不默认推定兼容。

| 稳定性检查 | 必须保持的行为 | 最小本机故障验收 |
| --- | --- | --- |
| 工具与reasoning配对 | toolCall ID、名称、完整参数、对应结果及先后顺序不乱、不孤立；供应商签名/opaque reasoning、thinking控制字段按协议原样保持，不擅造签名或把关闭要求说成上游已执行 | 一轮多toolCall+多结果、tool error、含opaque签名历史；压缩前后实际接收体逐项核，模型下一轮能合法接续 |
| 取消、断网与有界重试 | 取消能终止上游/压缩及worker，无后续请求或工具；上游断流/503按已声明有限策略结束，不多叠一层无界重试，不混用历史stop | 摘要等待中取消、流半途断开、连接拒绝、连续503；记录请求计数和终态，再重开检查 |
| 结果未知不重发 | 已派发工具/外部动作而回执丢失记unknown；代理重连、自动恢复、退回原生不能自动重复执行，审批不能重复消费 | mock工具先计数产生副作用再断流；恢复后计数仍为1、状态明确未知，需人工核对 |
| 代理失败与应用重启 | 代理退出、压缩异常、状态损坏/部分写入不冒充成功；旧配置可读；重启不自动重放未完成Run或已提交操作 | 强停代理、应用重开、空/截断状态文件、上游4xx；明确失败并保留原消息和检查点 |
| 重复压缩与还原 | 多次压缩不会逐轮抹掉关键规则、改变版本或重复工具结果。若声称无损/可还原，恢复原消息、tool ID/参数/结果及opaque块需实际验证；有损摘要不能宣称无损 | 同一材料两次压缩、重开再压缩、按包正式接口还原，核原内容hash/事实/工具配对；不能只还原填充文本 |
| 项目隔离与权限撤销 | 每项目独立代理状态、索引与会话，显式上游认证；授权撤销/来源版本变化继续拒绝；不能从其他项目或全局缓存补回资料 | 两项目不同哨兵、同时Run、项目切换及权限撤销后检索，外项目哨兵不得出现 |
| 退回原生保留完整历史 | 独立保留原始Pi历史和来源/ChangeSet检查点；退回原生可构建合法历史，不依赖已丢失ACP索引。压缩产物原子保存，不覆盖唯一原始副本 | 代理不可用后关闭B，用原始历史打开A并接续一轮；原历史hash、草稿及操作账本不变 |

回退只在尚未提交的新请求边界切换或显式恢复，不能流中失败后静默把同一请求再发一次。已有partial、tool动作或结果未知时先明确终态和检查点；不要用“自动退回”掩盖重复执行风险。当前原生单次压缩恢复与通用重试是各自有限机制，B要核清自己的重试与Pi是否叠加。

先过硬门：固定发布物确有可控API、显式上游凭据、仅loopback监听、无ambient全局配置/密钥发现；取消/超时/恢复/项目隔离、权限和共享预算无退化；当前支持协议与tool IDs/多模态语义不受损；许可署名能满足。任何硬门失败先停止替换。

随后才判断更好：同材料关键业务事实与限制均不退化，B在完整任务tokens或耗时存在可重复的明显改善，且另一项成本可接受，没有靠多次检索、增加窗口、扩大输出或删检查换收益。短本地fixture协议通过只能成为候选，**不代表长期运行稳定、全部模型协议稳定或可直接全量替换**；若当前仅有这些证据，应明确报告“尚未证明更好，保留原生”，而非因下载量或倍率替换。稳定性故障表逐项记录已测/未测，不能因“没有遇到”填写通过。

若本机已有能实际作摘要/业务回答的同一模型，可在零云边界内完成上述语义对照；否则如需实际供应商语义与计费效果，另由主任务确定明确授权与费用范围。本代理不会为比较自行读取既有凭据或发收费调用。无需为了实验先改产品运行底座。

通俗解释：两套办法都用同一堆资料、回答同一问题。必须先确认“重要规则没忘、不能改的没改”，再看总时间和总用量；把资料变短或接口接通，还不能说明工作做得更好。
