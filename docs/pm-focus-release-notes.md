# Slash 0.2.0 — 个人 PM 工作流收敛

日期：2026-10-02。当前阶段：本轮个人版交付完成；本地验收通过，外部渠道联调边界见下文。

## 这次改了什么

主入口收敛为会话、资源、成果和设置。独立评审、决策、流程图、知识库页面已撤下，原有记录、版本与底层能力保留。相关问题直接出现在会话或成果旁，可查看当前工作、项目历史、资料来源和处理记录。模板、共享文件夹仍可从辅助工具打开。

用户可以直接答复待确认问题。答复同时存入需求记录与会话，保存失败保留输入。检查意见的澄清和解决要求填写处理说明；旧版本意见可拒绝或继续澄清，不能无依据标记已在当前版本解决。

设置把常用质量开关前置，将模型分工、子任务上限、白名单、共享锁有效期收进默认关闭的高级区。没有重置已有配置，也没有删除归档会话管理、模型检查、连接开关和权限设置。

## 新增的会话工作流

| 动作 | 使用方式 | 真实输入与输出边界 |
| --- | --- | --- |
| 交互原型 | 输入区选择，填写范围与引用资料 | 复用 Pi 与草稿工具；支持元素引用和版本恢复 |
| 写 / 改 PRD | 指定模块，选现有业务资料、模板或 PRD | 缺失规则保留为待确认，避免默认扩展成整本 PRD |
| 整理资料 | 选择访谈、文档或填写研究目标 | 保留各份资料场景与来源；没有联网证据时不能声称做过外部研究 |
| 会议后整理 | 选择纪要、转写或笔记 | 区分已确认事项、问题和行动项；不虚构负责人/期限，不自动发消息 |
| 基于原型补 PRD | 在 HTML 预览工具栏发起 | 读取实际原型；界面无法证明的后台规则仍需确认 |
| 生成变更说明 | 从成果的实际版本差异发起 | 同一文件两个真实版本、确定性有序行差异，再让模型解释 |

Run 保存实际读取的路径、版本、哈希与截断信息。权限拒绝、来源变化和失效版本有明确失败状态。Plan 确认和恢复继承来源版本；变更后的资料必须重新核对。会议整理和原型补 PRD 要求实际文件，普通任务仍可自由对话。

## 修正的实际问题

- 研究 Plan 调用只读工具后，不再因调用次数非零被判为失败；写入仍被禁止。
- 原型预览允许本地表单事件，保留 `form-action 'none'`、`connect-src 'none'` 与不开放 `allow-same-origin` 的限制。已用真实按钮、必填校验、提交回显和外部提交阻断验证。
- 运行卡不再把未执行的质量/交付检查自动打勾；按来源回执和工具操作展示执行证据。
- 两处版本差异统计复用同一算法，能识别重复行与顺序变化，限制计算与输出体积。
- 成果列表支持在过程目录内登记的流程图，取消独立流程图页后仍可找到并预览。
- 窗口宽度小于 1500 时打开预览自动收起详情，用户仍可手动展开；模式/权限/模型菜单保持自定义样式和锚点。

## 质量检查的取舍

默认完整 PRD 章节、验收编号和映射缺项为建议；普通笔记不套用 PRD 检查。明确传给检查器的模板必填结构仍严格检查，模板迁移原有的结构约束保留。当前质量 IPC 没有自动绑定模板的 UI，不能把检查器参数支持说成已完成该流程。

空内容、稳定标识重复、无效 XML、版本冲突及外部操作结果未知继续受到保护。HTML 报告明确为静态检查，核心交互与业务正确性仍要实际试用。
