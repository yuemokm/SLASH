# Pi 复用检查

日期：2026-09-21。用户要求：自建内容与 Pi 重复时，优先采用更成熟稳定的实现，由工程判断。核对依据为已锁定安装的 `@earendil-works/pi-coding-agent` 0.86.1 的公开声明、实现及随包 SDK 文档，不根据工具名称猜测能力。

## 判断原则

优先使用公开 SDK 和工具工厂，使上游修复可以通过依赖升级进入项目。只有公开接口不能满足且收益明确时，才维护源码补丁或独立分支。复制 GitHub 仓库本身不代表复用了更多能力；关键是实际调用了哪些上游模块。

基础实现复用不取消产品约束。权限检查、审批、成果版本与外部回执是 slash 的责任；参考资料不能赋权。不能为减少本地代码而启用不经过网关的工具。

| 模块 | Pi 已有能力 | 判断 |
| --- | --- | --- |
| Agent 循环与流式调用 | createAgentSession、ModelRuntime | 已直接复用，继续保留；不自建推理循环 |
| 会话存储 | SessionManager | 已复用 Pi 会话文件；SQLite 仅承担业务会话、任务及成果关联，不替代 Pi 内部上下文格式 |
| Windows 命令执行 | createPowerShellToolDefinition、createLocalPowerShellOperations；上游已有超时、取消与进程树处理 | 优先复用，外层只增加应用权限、受限环境、记录与结果未知语义；具体接入需测试 |
| 普通文件读取 | createReadToolDefinition，支持 operations 注入、分页和输出截断 | 优先通过 operations 接入 Files 的真实路径授权与文本转换，避免重复实现分页与截断 |
| 多目录资料检索 | grep/find/ls 面向代码目录；grep 默认直接启动 ripgrep | 当前跨授权挂载、DOCX/PDF 正文搜索仍需业务适配，不能裸接默认递归扫描而绕过授权；后续可用独立检索适配提升性能 |
| 文件修改 | edit/write 直接文件修改、diff/patch | 成果提交保留 draft/apply、基准哈希和版本冲突；不能用直接写入替代。需要局部编辑时可复用上游编辑算法，提交仍走 ChangeSet |
| PDF / Word 提取、Word 导出 | 核心 read 不等于业务文档解析/交付 | 保留现有专用库与边界检查 |
| 工具权限与业务审批 | 工具扩展与包装入口 | 复用入口，应用维护自己的持久策略与确认状态；Pi 终端权限不等于产品目录授权 |
| 外部网页读取 | 当前核心工具集未提供对应网页抓取工具 | 保留有大小、超时与地址边界的网络适配，不假称这是 Pi 内置浏览能力 |
| CLI/MCP 注册、官方文档交付 | 通用工具和扩展可承载调用 | 保留产品注册表、官方渠道适配和回执语义；同一份配置用于会话与设置 |
| 多供应商桌面配置 | ModelRuntime 负责模型运行 | UI 分组、多配置 ID、Electron safeStorage 及旧配置迁移属桌面应用职责；继续复用运行层 |
| SMB 盘符、模板联动、PRD、评审 | 通用执行工具可作为底层 | 保留确定性业务流程，不重新开发上游已有的通用执行引擎 |

模型测试原先直接发 `/chat/completions`，与真实 Agent 的 Pi 调用路径重复且可能漂移。本轮决定统一通过 Pi 的模型运行配置与 `completeSimple` 测试连接。当前配置能力仍限定为 OpenAI 兼容接口，不因 Pi 支持其他协议就声称桌面表单已经支持所有原生供应商接口。

Pi 默认 AuthStorage 文件并不等于 Windows 系统加密存储，因此不直接替换 safeStorage。Pi models.json 的密钥字段还支持环境变量及命令解析；未经应用权限处理不能直接暴露给产品用户。模型运行依旧使用 `setRuntimeApiKey` 内存注入，独立配置 ID 与供应商显示分组分别管理。

## 需要特别验证

- 工具工厂的公开 `execute` 签名与运行上下文应按当前版本接入，不能靠类型断言跳过缺失上下文。
- `noTools` 与 `excludeTools` 配置不能误删包装后的工具，也不能同时暴露一条绕过权限的内置路径。
- 读取注入必须复核授权，而非只在工具创建时检查；长文截断应允许继续读取。
- 命令取消和超时不代表副作用回滚。输出文件、环境变量及错误消息须纳入凭据处理。
- Pi session 与 slash 业务状态有不同职责，当前尚未实现完整事件补读与恢复协议，不能声称二者已经完全统一。
